> **XHTTP** 是一种新兴的、高度可定制的底层传输代理协议（常用于科学上网、高性能隧道转发以及抗封锁代理工具如 Xray/V2Ray 生态中）。它的核心设计理念是**“全景式模拟真实 HTTP 流量”**，通过将代理数据完美地伪装成标准的 HTTP/1.1 或 HTTP/2 请求与响应，从而绕过深度包检测 (DPI, Deep Packet Inspection) 的封锁。

{% note info %}
**核心思想：**
*   **极致伪装：** 不仅复用真实的 HTTP 语义（Method, Path, Headers, Status Code），还能自定义分块传输（Chunked Transfer）、多路复用以及协议字段混淆。
*   **灵活性：** 允许用户精确控制 HTTP 报文的每一个角落，使得代理流量在防火墙眼中与普通的网页浏览或 API 调用毫无二致。
*   **解耦传输：** 将上层加密协议（如 VMess, VLESS, Trojan 等）与底层传输载体（TCP/TLS/HTTP）解耦，专注于提供强大的 HTTP 兼容载体。
{% endnote %}

## 一、为什么需要 XHTTP 协议？

在现代网络环境中，传统的代理协议（如早期的 Shadowsocks、未经伪装的 VMess）往往具有非常明显的“指纹”。防火墙通过深度包检测（DPI）和机器学习算法，能够轻易识别出这些协议的固定握手特征、包大小分布或固定的加密握手过程，进而对其进行阻断或限速。

为了对抗高强度的流量审查，网络工程师们开发了各种伪装技术：
1.  **WebSocket (WS) / gRPC：** 虽然借用了标准的 HTTP/1.1 或 HTTP/2 载体，但它们的握手行为（如固定的 Upgrade 头、特定的帧结构）在高阶审查面前依然容易暴露。
2.  **XTLS / Reality：** 尝试复用真实的 TLS 握手和证书，但配置复杂，且受限于 TLS 版本和密码套件。

**XHTTP** 的诞生正是为了填补这一空白。它不发明新的传输层，而是把 HTTP 协议的灵活性发挥到极致，允许代理流量“寄生”在几乎任何合法的 HTTP 交互模式中。

## 二、XHTTP 的工作原理与核心特性

XHTTP 的核心在于其**高度可配置性**和对标准 HTTP 协议的精准模仿。

### 2.1 流量分块与伪装 (Chunked Transfer)
在传输大流量数据时，XHTTP 可以利用 HTTP/1.1 的 `Transfer-Encoding: chunked` 特性，将代理数据切分成大小不一、带有随机填充的“数据块”。这使得流量的包大小分布和发送频率看起来就像是一个正在加载的大型网页或视频流，极大地干扰了基于流量统计特征的识别。

### 2.2 灵活的路由与分发 (Path & Headers)
XHTTP 允许客户端和服务器端自定义：
*   **HTTP 方法 (Method)：** 可以是常见的 `GET`、`POST`，甚至是较少使用的 `PUT` 或自定义方法。
*   **请求路径 (Path)：** 可以伪装成正常的 API 路径（如 `/api/v1/user/login` 或 `/static/js/app.js`）。
*   **自定义请求头 (Headers)：** 注入逼真的 `User-Agent`、`Accept-Language`、`Cookie` 等字段。

## 三、XHTTP 的配置示例（以 Xray 为例）

在主流代理工具（如 Xray-core）中，XHTTP 通常作为一种 `streamSettings` 的传输方式出现。以下是一个典型的服务端与客户端配置片段：

### 3.1 服务端配置片段 (JSON)

```json
{
  "inbounds": [
    {
      "port": 443,
      "protocol": "vless",
      "settings": {
        "clients": [
          {
            "id": "b831381d-6324-4d53-ad4f-8cda48b30811",
            "flow": "xtls-rprx-vision"
          }
        ],
        "encryption": "none"
      },
      "streamSettings": {
        "network": "xhttp",
        "xhttpSettings": {
          "path": "/my-secret-api-path",
          "host": "example.com"
        },
        "security": "tls",
        "tlsSettings": {
          "certificates": [
            {
              "certificateFile": "/path/to/cert.crt",
              "keyFile": "/path/to/key.key"
            }
          ]
        }
      }
    }
  ]
}

## 四、XHTTP 的优缺点分析

### 4.1 优点
1.  **极强的抗封锁能力：** 由于深度融合在标准的 HTTP 协议中，审查系统很难在海量的合法 Web 流量中精准剥离出 XHTTP 流量。
2.  **CDN 友好：** 可以无缝配合 Cloudflare 等 CDN 服务使用，隐藏真实服务器的 IP 地址。
3.  **多路复用支持：** 基于 HTTP/2 或 HTTP/3 时，能够享受多路复用带来的低延迟和高并发优势，避免 TCP 队头阻塞。
4.  **高度定制：** 运营者可以根据网络审查的严格程度随时调整伪装策略（如修改 Path、模拟不同的浏览器 Header）。

### 4.2 缺点与挑战
1.  **配置复杂：** 相比传统的直连协议，XHTTP 需要正确配置 TLS、证书、域名以及 HTTP 路径，对新手不够友好。
2.  **性能损耗：** 相比纯粹的裸协议（如原始 TCP/UDP），HTTP 报文的解析、TLS 握手以及可能的 CDN 转发会带来微小的延迟和 CPU 开销。
3.  **CDN 限制：** 如果配合公共 CDN（如 Cloudflare），大文件传输可能会受到 CDN 官方对于单连接上传/下载大小及超时的限制。

## 五、总结

**XHTTP** 是现代代理技术向“协议隐写”和“流量拟态”发展的重要产物。它通过对标准 HTTP/1.1 及 HTTP/2 协议的精准模拟和灵活控制，在保障传输性能的同时，为对抗高级网络审查提供了强大的武器。理解 XHTTP 的工作原理与配置方式，有助于更好地构建安全、稳定、隐蔽的网络通信链路。
